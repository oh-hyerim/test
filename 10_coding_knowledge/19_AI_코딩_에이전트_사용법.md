# AI 코딩 에이전트 사용법

## AI 코딩 에이전트란?

AI 코딩 에이전트는 사용자의 지시에 따라 프로젝트의 파일을 읽고, 코드를 작성하고, 수정하고, 실행과 테스트를 도와주는 AI 프로그램이다.

일반적인 대화형 AI보다 프로젝트 파일과 개발 도구를 활용해 실제 작업을 수행할 수 있다.

## AI 코딩 에이전트가 할 수 있는 일

AI 코딩 에이전트는 다음과 같은 작업을 도와줄 수 있다.

- 프로젝트 파일 읽기
- 파일과 폴더 구조 확인
- 새로운 파일 만들기
- 기존 코드 수정
- 오류 원인 분석
- 명령어 안내
- 테스트 실행
- 코드 설명
- 기능 추가
- 코드 정리
- 프로젝트 문서 작성

## AI에게 요청하기 전에 준비할 내용

AI에게 작업을 요청하기 전에 다음 내용을 정리하면 더 좋은 결과를 얻을 수 있다.

- 만들고 싶은 것
- 현재 프로젝트의 위치
- 사용 중인 프로그래밍 언어
- 원하는 기능
- 문제가 발생한 상황
- 오류 메시지
- 기대하는 결과
- 지켜야 할 조건

## 좋은 요청의 기본 구조

AI에게 다음 순서로 요청하면 좋다.

1. 현재 상황
2. 만들고 싶은 목표
3. 필요한 기능
4. 지켜야 할 조건
5. 원하는 결과

예시:

```text
현재 빈 웹 프로젝트를 열어두었습니다.

초보자도 사용할 수 있는 할 일 관리 웹페이지를 만들고 싶습니다.

필요한 기능은 다음과 같습니다.

- 할 일 입력
- 할 일 추가
- 할 일 완료 표시
- 할 일 삭제

먼저 현재 프로젝트 파일을 확인한 뒤, 작업 계획을 설명해주세요.
아직 파일을 수정하지 말고 계획만 보여주세요.
```

## 한 번에 한 가지 목표 요청하기

큰 작업을 한 번에 모두 요청하면 오류를 찾기 어려울 수 있다.

좋은 방법:

```text
먼저 현재 프로젝트 구조를 확인하고 설명해주세요.
아직 수정하지 마세요.
```

그다음:

```text
이제 화면의 기본 구조만 만들어주세요.
```

그다음:

```text
이제 할 일 추가 기능을 만들어주세요.
```

## 작업 전에 계획 요청하기

코드를 바로 수정하기 전에 작업 계획을 요청한다.

```text
이 작업을 시작하기 전에 필요한 작업을 작은 단계로 나누어 설명해주세요.
아직 파일은 수정하지 마세요.
```

계획에 포함되면 좋은 내용:

- 확인할 파일
- 수정할 파일
- 새로 만들 파일
- 사용할 기술
- 예상되는 영향
- 테스트 방법

## 기존 파일 먼저 읽게 하기

AI가 기존 코드를 모른 채 수정하면 프로젝트와 맞지 않는 코드를 만들 수 있다.

다음과 같이 요청한다.

```text
먼저 현재 프로젝트의 파일 구조와 주요 파일 내용을 확인해주세요.
확인하기 전에는 파일을 수정하지 마세요.
```

## 변경할 파일을 알려달라고 하기

작업 전에 어떤 파일이 변경되는지 확인한다.

```text
수정하거나 새로 만들 파일 목록을 먼저 알려주세요.
각 파일에서 무엇을 변경할지도 간단히 설명해주세요.
```

## 코드 수정 범위 제한하기

AI가 필요 이상으로 많은 파일을 수정하지 않도록 범위를 정한다.

```text
이번 작업에서는 필요한 파일만 수정해주세요.
관련 없는 파일은 변경하지 마세요.
기존 기능은 유지해주세요.
```

## 설명을 쉽게 요청하기

사용자가 코딩 초보자라면 설명 방식을 명확히 알려준다.

```text
저는 코딩 초보자입니다.
전문 용어를 사용하면 쉬운 말로 설명해주세요.
명령어를 알려줄 때는 어느 터미널에서 실행하는지도 알려주세요.
한 번에 한 단계씩 진행해주세요.
```

## 파일을 직접 수정할 때

AI에게 파일 수정을 요청하기 전에 다음을 확인한다.

- 올바른 프로젝트 폴더를 열었는가?
- 수정할 파일이 맞는가?
- 기존 파일을 읽었는가?
- 변경 목적이 분명한가?
- 변경 후 테스트 방법을 알고 있는가?

## 새 파일을 만들 때

새 파일을 만들 경우 다음 내용을 확인한다.

- 파일 이름
- 파일 확장자
- 파일을 저장할 폴더
- 파일의 역할
- 다른 파일과 연결되는 방법

예시:

```text
새 파일을 만들기 전에 파일 이름과 저장 위치를 알려주세요.
파일을 만든 뒤 어떤 역할을 하는지도 설명해주세요.
```

## 오류가 발생했을 때 AI에게 보여줄 내용

오류 해결을 요청할 때는 다음 정보를 함께 제공한다.

- 오류 메시지 전체
- 실행한 명령어
- 오류가 발생한 파일
- 오류가 발생한 시점
- 오류 전에 변경한 내용
- 기대한 결과
- 실제 결과

예시:

```text
Windows PowerShell에서 다음 명령어를 실행했습니다.

npm run dev

다음 오류가 발생했습니다.

여기에 오류 메시지 전체를 붙여넣습니다.

저는 개발 서버가 실행되기를 기대했습니다.
하지만 서버가 실행되지 않았습니다.
원인을 하나씩 확인해주세요.
```

## AI의 답변을 그대로 믿지 않기

AI가 알려준 코드나 명령어도 항상 확인해야 한다.

확인할 내용:

- 어떤 파일을 수정하는가?
- 어떤 명령어를 실행하는가?
- 파일이나 데이터가 삭제되는가?
- 외부 인터넷에 연결하는가?
- 비용이 발생할 수 있는가?
- API 키나 개인정보를 사용하는가?
- 현재 프로젝트와 호환되는가?

## 위험한 작업

다음 작업은 실행 전에 사용자에게 설명하고 확인을 받아야 한다.

- 파일이나 폴더 삭제
- 데이터베이스 데이터 삭제
- 대량 파일 변경
- Git 기록 강제 변경
- 외부 서비스에 데이터 전송
- 운영 서버 배포
- 공개 저장소에 코드 업로드
- 로그인이나 권한 변경
- 결제나 비용이 발생할 수 있는 작업

## 명령어 실행 원칙

AI가 터미널 명령어를 제안할 때는 다음 내용을 함께 설명해야 한다.

- 어느 터미널에서 실행하는가?
- 현재 어느 폴더에서 실행하는가?
- 명령어가 무엇을 하는가?
- 성공하면 어떤 결과가 나오는가?
- 오류가 나면 무엇을 확인하는가?

사용자는 의미를 모르는 명령어를 그대로 실행하지 않는다.

## 코드 작성 후 확인

AI가 코드를 작성하거나 수정한 뒤 다음을 확인한다.

1. 수정된 파일을 확인한다.
2. 오류가 없는지 확인한다.
3. 필요한 패키지가 설치되어 있는지 확인한다.
4. 프로그램을 실행한다.
5. 주요 기능을 직접 사용해본다.
6. 테스트를 실행한다.
7. 테스트 결과를 기록한다.

## 테스트하지 않은 것은 완료라고 말하지 않기

AI는 코드를 작성했다고 해서 기능이 정상이라고 말하지 않는다.

다음 상태를 구분한다.

- 코드를 작성함
- 오류 없이 빌드됨
- 테스트를 통과함
- 실제 기능을 확인함
- 배포됨

각 단계의 결과를 정확하게 설명한다.

## AI가 모르는 내용을 다룰 때

AI가 프로젝트에 없는 내용을 추측하지 않도록 한다.

```text
현재 파일에서 확인할 수 없는 내용은 추측하지 말고,
무엇을 확인해야 하는지 먼저 알려주세요.
```

최신 라이브러리나 외부 서비스의 사용법은 공식 문서를 확인하도록 요청한다.

## 작업 결과 보고

작업이 끝나면 AI는 다음 내용을 알려줘야 한다.

- 변경한 파일
- 새로 만든 파일
- 주요 변경 내용
- 실행한 명령어
- 실행 결과
- 테스트 결과
- 아직 해결되지 않은 문제
- 사용자가 다음에 할 일

## AI 코딩 에이전트와 Second Brain

Second Brain의 지식 파일은 AI가 작업할 때 참고할 수 있는 설명과 규칙을 제공한다.

관련된 지식 파일을 읽은 뒤 작업한다.

```text
이번 작업과 관련된 Second Brain 지식을 먼저 확인하고 작업해주세요.
```

현재 지식 파일에 없는 내용은 다음 순서로 처리한다.

1. 부족한 지식이 무엇인지 확인한다.
2. 필요한 내용을 설명받는다.
3. 지식 파일에 새 내용을 추가한다.
4. 추가한 지식을 읽는다.
5. 실제 작업에 적용한다.

## Ollama 로컬 모델 사용 원칙

현재 로컬 Ollama 모델은 사용자님의 컴퓨터에서 실행된다.

로컬 모델을 사용할 때 다음을 확인한다.

- Ollama 서버가 실행 중인가?
- 사용할 모델이 설치되어 있는가?
- 모델 이름이 정확한가?
- 모델이 응답하는가?
- 컴퓨터의 메모리가 충분한가?
- 모델의 응답이 너무 느리지 않은가?

현재 사용자님이 사용하는 모델 예시:

```text
gemma4:e2b
```

## AI 코딩 에이전트 작업 기본 규칙

AI 코딩 에이전트는 다음 순서로 작업한다.

1. 사용자의 목표를 쉬운 말로 정리한다.
2. 관련된 Second Brain 지식을 확인한다.
3. 프로젝트 폴더와 파일 구조를 확인한다.
4. 기존 코드를 읽는다.
5. 작업 계획을 제시한다.
6. 변경할 파일을 설명한다.
7. 사용자의 요청 범위 안에서 작업한다.
8. 수정 후 오류와 테스트를 확인한다.
9. 결과와 남은 문제를 설명한다.
10. 필요한 경우 새 지식을 Second Brain에 기록한다.

## 사용자와 AI의 협력 원칙

사용자는 목표와 원하는 결과를 설명한다.

AI는 필요한 작업을 계획하고 코드를 작성한다.

사용자는 위험한 변경과 외부 작업을 확인한다.

AI는 자신이 실행한 작업과 확인하지 못한 내용을 솔직하게 설명한다.

사용자와 AI 모두 모르는 내용을 추측하지 않고 확인하는 것을 우선한다.
