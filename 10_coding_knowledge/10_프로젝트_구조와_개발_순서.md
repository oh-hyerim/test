# 프로젝트 구조와 개발 순서

## 프로젝트란?

프로젝트는 특정한 목표를 이루기 위해 만든 프로그램이나 작업물이다.

예를 들어 다음은 각각 하나의 프로젝트가 될 수 있다.

- 개인 홈페이지
- 할 일 관리 앱
- 메모 앱
- 쇼핑몰
- 블로그
- AI 에이전트
- 자동화 프로그램

## 프로젝트 폴더란?

프로젝트 폴더는 하나의 프로그램을 만드는 데 필요한 파일과 폴더를 모아둔 공간이다.

프로젝트를 시작할 때는 관련 파일을 한 폴더 안에 정리하는 것이 좋다.

## 프로젝트 구조의 예시

간단한 웹 프로젝트는 다음과 같은 구조를 가질 수 있다.

```text
my-project/
├── index.html
├── style.css
├── script.js
└── README.md
```

각 파일의 역할은 다음과 같다.

- `index.html`: 웹페이지의 구조
- `style.css`: 웹페이지의 디자인
- `script.js`: 웹페이지의 동작
- `README.md`: 프로젝트 설명

## 파일과 폴더를 나누는 이유

파일과 폴더를 적절하게 나누면 다음과 같은 장점이 있다.

- 필요한 파일을 쉽게 찾을 수 있다.
- 코드의 역할을 구분할 수 있다.
- 여러 기능을 관리하기 쉽다.
- 수정할 부분을 빠르게 찾을 수 있다.
- 다른 사람이 프로젝트를 이해하기 쉽다.

## 기능을 작은 단위로 나누기

큰 기능은 작은 작업으로 나누어야 한다.

예를 들어 할 일 관리 앱은 다음과 같이 나눌 수 있다.

1. 할 일 입력창 만들기
2. 추가 버튼 만들기
3. 할 일 목록 표시하기
4. 할 일 완료 처리하기
5. 할 일 삭제하기
6. 데이터를 저장하기
7. 저장된 데이터를 불러오기

## 개발의 기본 순서

프로젝트는 보통 다음 순서로 개발한다.

1. 만들고 싶은 것을 정리한다.
2. 필요한 기능을 목록으로 작성한다.
3. 프로젝트 폴더를 만든다.
4. 기본 파일과 폴더를 만든다.
5. 가장 중요한 기능부터 만든다.
6. 프로그램을 실행한다.
7. 오류를 수정한다.
8. 기능을 테스트한다.
9. 화면과 코드를 정리한다.
10. 프로젝트를 저장하고 백업한다.

## 요구사항이란?

요구사항은 프로그램이 어떤 기능을 해야 하는지 설명한 것이다.

예를 들어 할 일 앱의 요구사항은 다음과 같다.

- 사용자는 할 일을 입력할 수 있어야 한다.
- 사용자는 추가 버튼을 눌러 할 일을 등록할 수 있어야 한다.
- 등록된 할 일은 목록에 표시되어야 한다.
- 사용자는 할 일을 삭제할 수 있어야 한다.
- 새로고침해도 할 일이 남아 있어야 한다.

## 작업 계획 세우기

코딩을 시작하기 전에 작업을 작은 단계로 나누는 것이 좋다.

작업 계획의 예:

```text
1. 현재 프로젝트 파일 확인
2. 필요한 화면 만들기
3. 입력 기능 만들기
4. 저장 기능 만들기
5. 삭제 기능 만들기
6. 실행 및 테스트
```

## 기존 프로젝트 확인

새 기능을 추가하기 전에 기존 프로젝트를 먼저 확인한다.

확인할 내용:

- 현재 파일 목록
- 프로젝트 실행 방법
- 사용 중인 프로그래밍 언어
- 설치된 패키지
- 기존 기능
- 설정 파일
- 오류 메시지

기존 코드를 확인하지 않고 새로운 코드를 작성하면 현재 프로젝트와 맞지 않을 수 있다.

## 변경 범위 정하기

작업을 시작하기 전에 어떤 파일을 수정할지 정한다.

가능하면 필요한 파일만 수정한다.

여러 파일을 동시에 수정해야 한다면 각 파일에서 무엇을 바꾸는지 먼저 설명한다.

## 실행과 확인

코드를 작성한 뒤에는 반드시 실행해본다.

확인할 내용:

- 프로그램이 실행되는가?
- 화면이 정상적으로 표시되는가?
- 버튼과 입력이 작동하는가?
- 오류 메시지가 나타나지 않는가?
- 기존 기능이 계속 작동하는가?

## README 파일

`README.md`는 프로젝트를 설명하는 파일이다.

README에는 다음 내용을 적을 수 있다.

- 프로젝트 이름
- 프로젝트가 하는 일
- 실행 방법
- 필요한 프로그램
- 주요 기능
- 사용 방법
- 주의사항

## 코딩 에이전트의 프로젝트 작업 원칙

코딩 에이전트는 프로젝트 작업을 시작할 때 다음 순서를 따른다.

1. 사용자의 목표를 확인한다.
2. 현재 프로젝트의 파일 구조를 확인한다.
3. 기존 코드와 설정 파일을 읽는다.
4. 프로젝트 실행 방법을 확인한다.
5. 필요한 작업을 작은 단계로 나눈다.
6. 필요한 파일만 수정한다.
7. 수정 후 프로그램을 실행한다.
8. 테스트 결과를 사용자에게 설명한다.

## 프로젝트 작업 시 주의사항

- 기존 파일을 읽지 않고 덮어쓰지 않는다.
- 사용하지 않는 파일을 함부로 삭제하지 않는다.
- 프로젝트의 실행 방법을 확인하지 않고 명령어를 바꾸지 않는다.
- 오류가 발생하면 오류 메시지를 기록한다.
- 중요한 변경 전에는 Git 커밋이나 백업을 고려한다.
- 테스트하지 않은 기능을 완성되었다고 말하지 않는다.
- 작업 결과와 남은 문제를 솔직하게 설명한다.
