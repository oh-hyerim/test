# 패키지와 의존성 관리

## 패키지란?

패키지는 다른 사람이 만들어 둔 기능을 프로젝트에서 사용할 수 있도록 묶어둔 코드이다.

예를 들어 다음과 같은 기능을 패키지로 추가할 수 있다.

- 웹 서버 만들기
- 날짜와 시간 처리
- 데이터베이스 연결
- 화면 구성
- 테스트 실행
- 파일 처리

## 의존성이란?

의존성은 프로젝트가 실행되기 위해 필요로 하는 외부 패키지이다.

프로젝트에서 특정 패키지를 사용하면 그 프로젝트는 해당 패키지에 의존한다고 말한다.

## npm이란?

npm은 JavaScript와 Node.js 패키지를 설치하고 관리하는 도구이다.

Node.js를 설치하면 보통 npm도 함께 설치된다.

npm 버전을 확인하는 명령어:

```powershell
npm --version
```

Node.js 버전을 확인하는 명령어:

```powershell
node --version
```

## package.json

`package.json`은 Node.js 프로젝트의 기본 설정 파일이다.

다음과 같은 정보를 저장한다.

- 프로젝트 이름
- 프로젝트 버전
- 실행 명령어
- 사용하는 패키지
- 개발에만 사용하는 패키지
- 프로젝트 설명

## 프로젝트 초기화

새로운 Node.js 프로젝트를 시작할 때 다음 명령어를 사용할 수 있다.

```powershell
npm init -y
```

이 명령어를 실행하면 기본적인 `package.json` 파일이 만들어진다.

## 패키지 설치

패키지를 설치할 때 다음 명령어를 사용한다.

```powershell
npm install 패키지이름
```

예를 들어 Express를 설치하려면 다음과 같이 입력한다.

```powershell
npm install express
```

패키지를 설치하면 보통 다음 두 가지가 변경된다.

- `package.json`에 패키지가 기록된다.
- `package-lock.json` 파일이 생성되거나 변경된다.

## 개발용 패키지

프로그램을 실행할 때는 필요하지 않고 개발할 때만 필요한 패키지는 개발용 의존성으로 설치한다.

```powershell
npm install --save-dev 패키지이름
```

예를 들어 테스트 도구나 코드 포맷팅 도구를 설치할 때 사용할 수 있다.

## node_modules 폴더

설치된 패키지의 실제 파일은 `node_modules` 폴더에 저장된다.

`node_modules` 폴더는 파일 수가 많고 크기가 커질 수 있다.

일반적으로 `node_modules` 폴더는 GitHub에 올리지 않는다.

`.gitignore` 파일에 다음 내용을 추가한다.

```text
node_modules/
```

## package-lock.json

`package-lock.json`은 설치된 패키지와 하위 패키지의 정확한 버전을 기록하는 파일이다.

다른 컴퓨터에서 같은 프로젝트를 설치할 때 비슷한 환경을 재현하는 데 도움을 준다.

일반적인 프로젝트에서는 `package-lock.json`을 Git에 포함하는 것이 좋다.

## package.json의 scripts

`package.json`의 `scripts`에는 자주 사용하는 명령어를 짧은 이름으로 등록할 수 있다.

예시:

```json
{
  "scripts": {
    "start": "node index.js",
    "dev": "node --watch index.js",
    "test": "node test.js"
  }
}
```

등록한 명령어는 다음과 같이 실행한다.

```powershell
npm run start
```

```powershell
npm run dev
```

```powershell
npm run test
```

`start`처럼 자주 사용하는 명령어는 다음처럼 실행할 수도 있다.

```powershell
npm start
```

## package.json 확인하기

새 패키지를 설치하거나 프로젝트를 실행하기 전에 `package.json`을 확인한다.

확인할 내용:

- 프로젝트가 사용하는 실행 명령어
- 설치된 패키지
- 개발용 패키지
- 프로젝트의 시작 파일
- Node.js 버전 조건

## 패키지 설치 오류

패키지 설치 중 오류가 발생하면 다음을 확인한다.

1. 인터넷 연결 상태
2. 패키지 이름의 철자
3. 현재 폴더가 프로젝트 폴더인지
4. `package.json` 파일이 있는지
5. Node.js와 npm이 설치되어 있는지
6. 오류 메시지 전체
7. 디스크 공간
8. 패키지가 현재 운영체제를 지원하는지

현재 폴더를 확인하는 PowerShell 명령어:

```powershell
Get-Location
```

현재 폴더의 파일을 확인하는 PowerShell 명령어:

```powershell
Get-ChildItem
```

## 패키지 다시 설치하기

`package.json`에 기록된 패키지를 설치하려면 다음 명령어를 사용한다.

```powershell
npm install
```

이 명령어는 `package.json`과 `package-lock.json`을 바탕으로 필요한 패키지를 설치한다.

## 패키지 삭제하기

패키지를 삭제하려면 다음 명령어를 사용한다.

```powershell
npm uninstall 패키지이름
```

패키지를 삭제하기 전에는 해당 패키지를 다른 코드에서 사용하고 있는지 확인한다.

## 패키지 업데이트

패키지를 업데이트할 때는 현재 프로젝트와 호환되는지 먼저 확인한다.

```powershell
npm update
```

모든 패키지를 무조건 최신 버전으로 바꾸면 기존 코드가 작동하지 않을 수 있다.

## 버전 관리

패키지 버전은 보통 다음과 같은 형식을 사용한다.

```text
major.minor.patch
```

예:

```text
1.4.2
```

일반적인 의미:

- major: 큰 변경이나 호환되지 않는 변경
- minor: 기존 기능과 호환되는 새로운 기능
- patch: 오류 수정이나 작은 변경

패키지를 업데이트하기 전에는 변경 내용을 확인한다.

## 전역 설치와 프로젝트 설치

프로젝트에서만 사용할 패키지는 보통 프로젝트 안에 설치한다.

```powershell
npm install 패키지이름
```

여러 프로젝트에서 공통으로 사용할 명령줄 도구는 전역 설치를 할 수도 있다.

```powershell
npm install --global 패키지이름
```

초보자는 필요한 이유를 확인하지 않은 채 패키지를 전역 설치하지 않는다.

## 보안 주의사항

패키지를 설치하기 전에 다음을 확인한다.

- 패키지 이름이 정확한가?
- 공식 패키지인가?
- 프로젝트에서 정말 필요한가?
- 최근에 관리되고 있는가?
- 알려진 보안 문제가 있는가?
- 설치 과정에서 이상한 명령어를 실행하지 않는가?

인터넷에서 복사한 패키지 설치 명령어를 의미도 모른 채 실행하지 않는다.

## 코딩 에이전트의 패키지 관리 원칙

코딩 에이전트는 패키지를 설치하기 전에 다음 내용을 설명한다.

- 설치할 패키지 이름
- 패키지가 필요한 이유
- 실행할 명령어
- 프로젝트에 생기는 변경사항
- 보안이나 비용과 관련된 주의사항

코딩 에이전트는 다음 작업을 사용자 확인 없이 실행하지 않는다.

- 필요성이 불분명한 패키지 대량 설치
- 패키지 전체 업데이트
- 전역 패키지 설치
- 패키지 삭제
- 설치 스크립트 실행
- 출처가 불분명한 패키지 설치

## 패키지 설치 후 확인

패키지를 설치한 뒤 다음을 확인한다.

1. 설치 명령어가 성공했는가?
2. `package.json`이 예상대로 변경되었는가?
3. `package-lock.json`이 변경되었는가?
4. 프로그램이 실행되는가?
5. 기존 기능이 계속 작동하는가?
6. 새로운 오류가 발생하지 않는가?

테스트하지 않은 패키지 설치가 프로젝트에 문제를 일으키지 않았다고 단정하지 않는다.
