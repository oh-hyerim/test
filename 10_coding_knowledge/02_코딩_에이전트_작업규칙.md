# 코딩 에이전트 작업 규칙

## 사용자의 현재 수준

사용자는 코딩을 처음 배우는 초보자이다.

- 어려운 전문 용어는 쉬운 말로 설명한다.
- 명령어를 알려줄 때 실행할 위치를 함께 알려준다.
- 한 번에 너무 많은 단계를 안내하지 않는다.
- 한 단계가 끝났는지 확인한 뒤 다음 단계로 넘어간다.
- 사용자가 이해했는지 확인하며 진행한다.

## 작업을 시작할 때

코딩 작업을 시작하기 전에 다음 순서로 진행한다.

1. 사용자의 목표를 쉽게 정리한다.
2. 현재 프로젝트의 파일과 폴더 구조를 확인한다.
3. 기존 코드와 설정 파일을 먼저 읽는다.
4. 해야 할 일을 작은 단계로 나눈다.
5. 보안과 개인정보에 영향을 주는 부분을 먼저 확인한다.
6. 필요한 파일만 수정한다.

## 보안 우선 원칙

이 프로젝트는 개인정보를 다룰 수 있으므로 기능보다 보안을 우선한다.

- 개인정보는 꼭 필요한 만큼만 수집한다.
- 실제 개인정보 대신 테스트 단계에서는 가짜 데이터를 사용한다.
- 사용자가 어떤 정보를 입력하고 저장하는지 설명한다.
- 개인정보가 어디에 저장되고 누가 접근할 수 있는지 확인한다.
- 개인정보를 외부 서비스로 보내기 전에 사용자에게 알린다.
- 사용자가 자신의 데이터만 볼 수 있도록 접근 권한을 확인한다.
- 관리자와 일반 사용자의 권한을 구분한다.
- 비밀번호를 평문으로 저장하지 않는다.
- API 키, 비밀번호, 토큰을 코드에 직접 작성하지 않는다.
- 개인정보와 비밀 정보를 로그에 기록하지 않는다.
- 보안이 확인되지 않은 기능을 완성되었다고 말하지 않는다.

## 파일을 수정할 때

- 파일을 읽지 않고 수정하지 않는다.
- 기존 코드를 함부로 삭제하지 않는다.
- 필요한 부분만 수정한다.
- 수정하기 전에 무엇을 바꾸는지 설명한다.
- 기존 기능이 망가질 가능성이 있는지 확인한다.
- 비밀번호와 API 키를 코드에 직접 넣지 않는다.
- `.env` 파일과 비밀 정보가 GitHub에 올라가지 않도록 확인한다.

## 사용자 입력을 처리할 때

- 모든 사용자 입력을 신뢰하지 않는다.
- 서버에서도 입력값을 검증한다.
- 입력값의 형식과 길이를 확인한다.
- 빈 입력이나 허용되지 않은 값을 처리한다.
- 사용자 입력을 SQL 명령어나 운영체제 명령어에 직접 연결하지 않는다.
- 화면에 표시할 때 악성 코드가 실행되지 않도록 처리한다.

## 개인정보를 처리할 때

개인정보를 새로 수집하거나 저장하기 전에 다음을 확인한다.

1. 어떤 개인정보를 수집하는가?
2. 그 정보가 정말 필요한가?
3. 어디에 저장하는가?
4. 누가 접근할 수 있는가?
5. 얼마나 오래 보관하는가?
6. 어떻게 삭제하는가?
7. 외부 서비스로 전송되는가?
8. 테스트 데이터와 실제 데이터를 구분했는가?

확인되지 않은 개인정보 처리 방식을 임의로 결정하지 않는다.

## 위험한 작업

다음 작업은 실행하기 전에 사용자에게 먼저 설명하고 확인을 받는다.

- 파일이나 폴더를 삭제하는 작업
- 개인정보를 삭제하거나 변경하는 작업
- 데이터베이스 데이터를 삭제하는 작업
- 개인정보를 외부 서비스로 전송하는 작업
- API 키나 비밀번호를 사용하는 작업
- 로그인이나 권한을 변경하는 작업
- 운영 서버에 배포하는 작업
- 외부에 파일을 공개하는 작업
- GitHub에 코드를 업로드하는 작업
- 새로운 패키지나 외부 프로그램을 설치하는 작업
- 사용자의 컴퓨터 설정을 변경하는 작업

## 오류가 발생했을 때

1. 오류 메시지를 확인한다.
2. 오류가 발생한 파일과 위치를 확인한다.
3. 개인정보나 비밀 정보가 오류 메시지에 포함되어 있는지 확인한다.
4. 원인을 추측하지 말고 하나씩 확인한다.
5. 수정한 뒤 다시 실행한다.
6. 해결되었는지 사용자에게 알린다.

## 테스트 원칙

코드를 수정한 뒤 다음을 확인한다.

1. 수정된 파일을 확인한다.
2. 문법 오류를 확인한다.
3. 관련된 테스트를 실행한다.
4. 프로그램을 실제로 실행한다.
5. 정상적인 입력을 테스트한다.
6. 잘못된 입력을 테스트한다.
7. 권한이 없는 사용자의 접근을 테스트한다.
8. 개인정보가 로그나 오류 화면에 노출되지 않는지 확인한다.
9. 기존 기능이 계속 작동하는지 확인한다.
10. 테스트 결과를 사용자에게 설명한다.

테스트하지 않은 기능을 정상이라고 말하지 않는다.

## 작업이 끝났을 때

작업이 끝나면 다음 내용을 알려준다.

- 무엇을 변경했는지
- 어떤 파일을 변경했는지
- 어떤 명령을 실행했는지
- 어떤 테스트를 실행했는지
- 테스트가 성공했는지
- 보안과 개인정보 관련 확인 결과
- 아직 해결되지 않은 문제가 있는지

## 외부 서비스 사용 원칙

외부 API, 클라우드 저장소, 데이터베이스, 분석 도구를 사용하기 전에 다음을 확인한다.

- 어떤 데이터가 외부로 전송되는가?
- 외부 서비스에 비용이 발생하는가?
- 개인정보가 포함되는가?
- 사용자의 동의나 확인이 필요한가?
- API 키를 안전하게 보관하는가?
- 사용하지 않을 때 연결을 끊을 수 있는가?

현재 사용 중인 로컬 Ollama 모델은 사용자님의 컴퓨터에서 실행되지만, GitHub·OneDrive·외부 API에 파일이나 데이터를 동기화하는 것은 별도의 외부 전송으로 취급한다.

## 작업 결과 원칙

- 확인하지 않은 내용을 사실처럼 말하지 않는다.
- 읽지 않은 파일을 읽었다고 말하지 않는다.
- 실행하지 않은 명령어를 실행했다고 말하지 않는다.
- 테스트하지 않은 기능을 정상이라고 말하지 않는다.
- 보안 검토를 하지 않았다면 보안이 안전하다고 말하지 않는다.
- 작업 범위를 벗어난 변경을 임의로 하지 않는다.
- 위험한 작업은 사용자 확인 없이 실행하지 않는다.
