# 테스트와 품질관리

## 테스트란?

테스트는 프로그램이 의도한 대로 작동하는지 확인하는 과정이다.

코드를 작성했다고 바로 완성된 것으로 판단하지 않는다. 실제로 실행하고 여러 상황에서 확인해야 한다.

## 테스트가 필요한 이유

테스트를 하면 다음과 같은 문제를 빨리 찾을 수 있다.

- 기능이 작동하지 않는 문제
- 특정 입력에서 오류가 발생하는 문제
- 기존 기능이 수정 후 망가지는 문제
- 사용자에게 잘못된 결과를 보여주는 문제
- 프로그램을 배포한 뒤 발생할 수 있는 문제

## 테스트의 기본 순서

1. 무엇을 확인할지 정한다.
2. 예상되는 결과를 정한다.
3. 프로그램을 실행한다.
4. 실제 결과를 확인한다.
5. 예상 결과와 실제 결과를 비교한다.
6. 문제가 있으면 수정한다.
7. 수정한 뒤 다시 테스트한다.

## 정상적인 경우 테스트하기

사용자가 일반적인 값을 입력했을 때 제대로 작동하는지 확인한다.

예를 들어 로그인 기능이라면 다음을 테스트한다.

- 올바른 이메일과 비밀번호 입력
- 존재하는 사용자로 로그인
- 정상적인 형식의 게시글 작성

## 잘못된 경우 테스트하기

사용자가 잘못된 값을 입력했을 때 프로그램이 적절하게 대응하는지 확인한다.

예:

- 빈 입력
- 잘못된 이메일 형식
- 너무 긴 입력
- 존재하지 않는 사용자
- 잘못된 비밀번호
- 허용되지 않은 파일 형식

프로그램이 갑자기 종료되지 않고 사용자에게 이해할 수 있는 안내를 보여줘야 한다.

## 경계값 테스트

허용되는 값의 가장 작거나 큰 값을 테스트한다.

예를 들어 비밀번호가 8자 이상이어야 한다면 다음을 확인한다.

- 7자 비밀번호
- 정확히 8자 비밀번호
- 9자 비밀번호

## 단위 테스트

단위 테스트는 함수나 작은 기능 하나를 따로 테스트하는 것이다.

예를 들어 더하기 함수가 있다면 여러 숫자를 넣고 결과가 올바른지 확인한다.

```javascript
function add(a, b) {
  return a + b;
}

console.log(add(2, 3));
```

예상 결과:

```text
5
```

## 통합 테스트

통합 테스트는 여러 기능이 함께 연결되어 작동하는지 확인하는 것이다.

예를 들어 로그인 기능은 다음 기능들이 함께 연결되어야 한다.

- 로그인 화면
- 서버 요청
- 사용자 확인
- 데이터베이스 조회
- 로그인 성공 또는 실패 응답

각 기능이 따로 작동하더라도 서로 연결했을 때 문제가 생길 수 있으므로 통합 테스트가 필요하다.

## 수동 테스트

사람이 직접 프로그램을 실행하고 기능을 확인하는 방법이다.

예:

1. 웹사이트를 연다.
2. 로그인 화면으로 이동한다.
3. 아이디와 비밀번호를 입력한다.
4. 로그인 버튼을 누른다.
5. 로그인 결과를 확인한다.

## 자동 테스트

프로그램이 테스트 코드를 실행해서 결과를 자동으로 확인하는 방법이다.

자동 테스트를 사용하면 코드를 수정할 때마다 기존 기능이 정상인지 빠르게 확인할 수 있다.

## 린트와 포맷팅

### 린트

린트는 코드에서 문법 오류나 문제가 될 가능성이 있는 부분을 찾아주는 도구이다.

### 포맷팅

포맷팅은 들여쓰기와 줄바꿈을 일정한 규칙으로 정리하는 것이다.

린트와 포맷팅은 코드의 품질과 가독성을 높이는 데 도움을 준다.

## 타입 검사

TypeScript 같은 언어에서는 값의 종류가 올바른지 확인할 수 있다.

예를 들어 숫자를 사용해야 하는 곳에 글자를 넣으면 타입 오류가 발생할 수 있다.

타입 검사는 실행하기 전에 일부 오류를 찾는 데 도움을 준다.

## 회귀 버그

회귀 버그는 새로운 기능을 추가하거나 코드를 수정한 뒤에 기존에 작동하던 기능이 망가지는 문제이다.

코드를 수정한 뒤에는 새 기능뿐 아니라 기존 기능도 다시 확인해야 한다.

## 테스트 결과 기록

테스트를 끝낸 뒤 다음 내용을 기록하면 좋다.

- 테스트한 기능
- 입력한 값
- 예상 결과
- 실제 결과
- 성공 또는 실패 여부
- 발견된 오류
- 수정한 내용

## 코딩 에이전트의 테스트 원칙

코딩 에이전트는 코드를 수정한 뒤 다음 순서로 작업한다.

1. 수정한 파일을 확인한다.
2. 문법 오류를 확인한다.
3. 관련된 테스트를 실행한다.
4. 프로그램을 실제로 실행한다.
5. 핵심 기능을 확인한다.
6. 테스트 결과를 사용자에게 설명한다.

테스트를 실행하지 않았다면 테스트했다고 말하지 않는다.

## 테스트할 때 주의할 점

- 실제 운영 데이터에 테스트하지 않는다.
- 테스트 전에 중요한 데이터를 백업한다.
- 테스트용 계정과 운영 계정을 구분한다.
- API 키와 비밀번호를 테스트 코드에 직접 넣지 않는다.
- 오류가 발생하면 오류 메시지를 기록한다.
- 한 번에 너무 많은 부분을 바꾸지 않는다.
- 문제가 해결되었는지 같은 방법으로 다시 확인한다.
