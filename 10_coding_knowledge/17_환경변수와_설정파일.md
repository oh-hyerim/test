# 환경변수와 설정 파일

## 환경변수란?

환경변수는 프로그램이 실행될 때 사용하는 값을 코드 파일 밖에 저장하는 방법이다.

프로그램의 실행 환경에 따라 달라지는 값이나 외부에 공개하면 안 되는 값을 관리할 때 사용할 수 있다.

## 환경변수를 사용하는 이유

환경변수를 사용하면 다음과 같은 장점이 있다.

- 비밀번호를 코드에 직접 작성하지 않을 수 있다.
- API 키를 코드와 분리할 수 있다.
- 개발 환경과 운영 환경의 설정을 다르게 사용할 수 있다.
- 코드를 공개 저장소에 올려도 중요한 정보가 노출될 가능성을 줄일 수 있다.

## 환경변수의 예

다음과 같은 값을 환경변수로 관리할 수 있다.

- 서버 포트
- 데이터베이스 주소
- API 키
- 비밀번호
- 외부 서비스 주소
- 개발 또는 운영 환경 구분값

## PowerShell에서 환경변수 설정하기

현재 열려 있는 PowerShell 창에서만 사용할 환경변수는 다음과 같이 설정한다.

```powershell
$env:APP_MODE="development"
```

설정된 값을 확인하려면 다음과 같이 입력한다.

```powershell
$env:APP_MODE
```

현재 PowerShell 창을 닫으면 이 방식으로 설정한 값은 사라질 수 있다.

## Windows 사용자 환경변수 저장하기

Windows 사용자 계정에 환경변수를 저장하려면 다음과 같이 입력할 수 있다.

```powershell
[Environment]::SetEnvironmentVariable("APP_MODE", "development", "User")
```

새 터미널을 연 뒤 값을 확인한다.

```powershell
[Environment]::GetEnvironmentVariable("APP_MODE", "User")
```

환경변수를 새로 저장하거나 변경한 뒤에는 실행 중인 프로그램을 다시 시작해야 할 수 있다.

## Node.js에서 환경변수 사용하기

Node.js에서는 `process.env`를 사용해 환경변수를 읽는다.

```javascript
const port = process.env.PORT || 3000;

console.log(`서버 포트: ${port}`);
```

`PORT` 환경변수가 설정되어 있으면 그 값을 사용하고, 없으면 `3000`을 사용한다.

## .env 파일

Node.js 프로젝트에서는 환경변수를 `.env` 파일에 저장할 수 있다.

예시:

```text
PORT=3000
APP_MODE=development
DATABASE_URL=데이터베이스_주소
```

실제 API 키나 비밀번호가 들어 있는 `.env` 파일은 GitHub에 공개하지 않는다.

## .gitignore에 .env 추가하기

`.env` 파일이 Git에 포함되지 않도록 `.gitignore` 파일에 다음 내용을 추가한다.

```text
.env
.env.*
!.env.example
```

프로젝트 상황에 따라 `.env.example`을 공개할 수 있다.

## .env.example 파일

`.env.example`은 필요한 환경변수의 이름만 보여주는 예시 파일이다.

실제 비밀번호나 API 키는 넣지 않는다.

예시:

```text
PORT=3000
APP_MODE=development
DATABASE_URL=여기에_데이터베이스_주소
API_KEY=여기에_API_키
```

다른 사람이 프로젝트를 실행할 때 어떤 환경변수가 필요한지 알 수 있도록 도와준다.

## 기본값 사용하기

환경변수가 없을 때 사용할 기본값을 정할 수 있다.

```javascript
const port = process.env.PORT || 3000;
const appMode = process.env.APP_MODE || "development";
```

기본값을 사용해도 되는 값과 반드시 설정해야 하는 값을 구분해야 한다.

## 필수 환경변수 확인하기

반드시 필요한 환경변수가 없으면 프로그램을 시작할 때 알려주는 것이 좋다.

```javascript
const databaseUrl = process.env.DATABASE_URL;

if (!databaseUrl) {
  throw new Error("DATABASE_URL 환경변수가 필요합니다.");
}
```

## 개발 환경과 운영 환경

개발 환경은 프로그램을 만들고 테스트하는 환경이다.

운영 환경은 실제 사용자가 이용하는 환경이다.

두 환경의 설정은 다를 수 있다.

예:

```text
개발 환경:
APP_MODE=development

운영 환경:
APP_MODE=production
```

## 환경변수 보안 원칙

- 실제 API 키를 코드에 직접 작성하지 않는다.
- 실제 비밀번호를 GitHub에 올리지 않는다.
- `.env` 파일을 `.gitignore`에 추가한다.
- 환경변수 값을 채팅창이나 공개 문서에 그대로 붙여넣지 않는다.
- 이미 공개된 키는 새로 발급한다.
- 환경변수 이름과 값을 구분한다.
- 필요한 프로그램만 환경변수를 읽도록 한다.

## 현재 로컬 Ollama와의 관계

현재 사용 중인 로컬 Ollama 모델은 사용자님의 컴퓨터에서 실행된다.

따라서 `gemma4:e2b`를 로컬로 실행하고 안티그래비티에서 사용하는 데 외부 AI 서비스 API 키는 필요하지 않다.

Ollama 실행 설정도 환경변수로 지정할 수 있다.

```powershell
$env:OLLAMA_LLM_LIBRARY="cpu_avx2"
```

위 설정은 Ollama가 사용할 실행 방식을 지정하는 예시이다.

## 설정 파일 작업 원칙

코딩 에이전트는 설정 파일을 수정하기 전에 다음을 확인한다.

1. 설정 파일의 현재 내용을 읽는다.
2. 각 설정이 어떤 역할을 하는지 확인한다.
3. 개발 환경과 운영 환경 중 어느 곳에 적용되는지 확인한다.
4. 비밀 정보가 포함되어 있는지 확인한다.
5. 필요한 부분만 수정한다.
6. 수정 후 프로그램을 다시 실행해 확인한다.

## 환경변수 오류가 발생했을 때

환경변수가 작동하지 않으면 다음을 확인한다.

- 변수 이름의 철자가 맞는가?
- 현재 터미널에 설정되어 있는가?
- 새 터미널을 열었는가?
- 프로그램을 다시 시작했는가?
- `.env` 파일이 올바른 위치에 있는가?
- `.env` 파일을 프로그램이 읽도록 설정했는가?
- 값에 불필요한 공백이나 따옴표가 들어갔는가?

확인하지 않은 환경변수 값이나 보안 상태를 정상이라고 단정하지 않는다.
