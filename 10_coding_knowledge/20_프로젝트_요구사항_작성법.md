# 프로젝트 요구사항 작성법

## 요구사항이란?

요구사항은 프로젝트가 어떤 기능을 해야 하는지 설명하는 내용이다.

프로젝트를 만들기 전에 요구사항을 정리하면 무엇을 만들어야 하는지 분명해지고, 작업 중에 방향이 바뀌는 것을 줄일 수 있다.

## 프로젝트 목표

프로젝트를 시작하기 전에 프로젝트가 해결하려는 문제와 목표를 정한다.

좋은 목표의 예:

```text
사용자가 오늘 해야 할 일을 쉽게 기록하고 완료 여부를 관리할 수 있는 웹앱을 만든다.
```

불분명한 목표의 예:

```text
좋은 앱을 만든다.
```

목표는 누가 사용하고 무엇을 해결하는지 포함하는 것이 좋다.

## 사용자

프로젝트를 사용할 사람이 누구인지 정한다.

예:

- 코딩을 처음 배우는 사람
- 혼자 일하는 사람
- 학생
- 온라인 판매자
- 팀 구성원
- 일반 웹사이트 방문자

사용자를 정하면 화면과 기능을 결정하기 쉬워진다.

## 핵심 기능

프로젝트에 꼭 필요한 기능을 먼저 정한다.

할 일 관리 앱의 핵심 기능 예:

- 할 일 입력
- 할 일 추가
- 할 일 목록 표시
- 할 일 완료 처리
- 할 일 삭제
- 할 일 저장
- 저장된 할 일 불러오기

처음부터 모든 기능을 넣기보다 핵심 기능부터 만든다.

## 부가 기능

핵심 기능이 작동한 뒤 추가할 기능을 정한다.

예:

- 할 일 검색
- 마감일 설정
- 중요도 설정
- 카테고리 분류
- 알림
- 다크 모드
- 데이터 내보내기

부가 기능은 핵심 기능보다 나중에 구현한다.

## 기능 요구사항

기능 요구사항은 프로그램이 해야 하는 동작을 설명한다.

예:

```text
사용자는 입력창에 할 일을 입력할 수 있어야 한다.
사용자가 추가 버튼을 누르면 할 일이 목록에 추가되어야 한다.
사용자는 완료된 할 일을 구분할 수 있어야 한다.
사용자는 목록에서 할 일을 삭제할 수 있어야 한다.
```

기능은 가능한 한 구체적으로 작성한다.

## 비기능 요구사항

비기능 요구사항은 기능 외에 프로그램이 갖추어야 할 조건이다.

예:

- 화면은 모바일과 컴퓨터에서 모두 보여야 한다.
- 버튼을 눌렀을 때 빠르게 반응해야 한다.
- 사용자의 비밀번호를 안전하게 저장해야 한다.
- 오류가 발생하면 이해하기 쉬운 안내를 보여줘야 한다.
- 중요한 데이터는 삭제 전에 확인해야 한다.

## 화면 요구사항

필요한 화면을 목록으로 정리한다.

예:

```text
1. 홈 화면
2. 로그인 화면
3. 회원가입 화면
4. 사용자 정보 화면
5. 설정 화면
```

각 화면에서 보여줄 내용과 할 수 있는 동작도 정리한다.

## 사용자 흐름

사용자가 프로그램을 어떻게 이용하는지 순서대로 작성한다.

예:

```text
1. 사용자가 웹사이트를 연다.
2. 로그인 화면에서 이메일과 비밀번호를 입력한다.
3. 로그인 버튼을 누른다.
4. 서버가 사용자 정보를 확인한다.
5. 로그인에 성공하면 홈 화면으로 이동한다.
6. 로그인에 실패하면 오류 메시지를 보여준다.
```

사용자 흐름을 정리하면 필요한 화면과 기능을 빠뜨릴 가능성이 줄어든다.

## 입력과 출력

각 기능에서 어떤 입력을 받고 어떤 결과를 보여주는지 정한다.

예:

```text
기능: 할 일 추가

입력:
- 할 일 내용

처리:
- 입력값이 비어 있는지 확인
- 할 일을 저장
- 목록에 추가

출력:
- 새 할 일이 목록에 표시됨
```

## 성공 조건

기능이 완성되었다고 판단할 기준을 정한다.

예:

```text
할 일 추가 기능의 성공 조건:

- 사용자가 내용을 입력할 수 있다.
- 빈 내용은 추가되지 않는다.
- 추가 버튼을 누르면 목록에 표시된다.
- 새로고침 후에도 저장된 내용이 남아 있다.
```

성공 조건은 나중에 테스트할 때 사용한다.

## 오류 상황

정상적인 경우뿐 아니라 오류가 발생할 때의 동작도 정한다.

예:

```text
- 입력값이 비어 있으면 안내 메시지를 표시한다.
- 서버 요청이 실패하면 오류 메시지를 표시한다.
- 로그인 정보가 틀리면 다시 입력하도록 안내한다.
- 요청한 데이터를 찾지 못하면 찾을 수 없다고 표시한다.
```

## 우선순위

기능을 중요도에 따라 나눈다.

### 필수 기능

없으면 프로젝트의 기본 목적을 달성할 수 없는 기능이다.

예:

- 로그인
- 데이터 저장
- 핵심 화면
- 주요 작업 기능

### 중요 기능

있으면 사용성이 좋아지지만 처음부터 반드시 필요한 것은 아닌 기능이다.

예:

- 검색
- 정렬
- 필터
- 알림

### 나중에 추가할 기능

기본 기능이 완성된 뒤 추가할 수 있는 기능이다.

예:

- 다크 모드
- 고급 통계
- 외부 서비스 연동
- 자동화 기능

## 최소 기능 제품

최소 기능 제품은 프로젝트의 핵심 목적을 확인할 수 있는 가장 작은 버전이다.

예를 들어 할 일 앱의 최소 기능 제품은 다음과 같다.

- 할 일 입력
- 할 일 추가
- 할 일 목록 표시
- 할 일 삭제

처음부터 로그인, 알림, 통계, 공유 기능을 모두 만들 필요는 없다.

## 기술 요구사항

프로젝트에서 사용할 기술을 정한다.

예:

```text
화면:
- React
- TypeScript
- CSS

서버:
- Node.js
- Express

데이터:
- SQLite

개발 도구:
- Git
- npm
```

기술을 선택할 때는 프로젝트의 크기와 사용자의 수준을 고려한다.

## 데이터 요구사항

저장해야 하는 데이터의 종류를 정한다.

예:

```text
사용자:
- id
- name
- email
- createdAt

할 일:
- id
- title
- completed
- userId
- createdAt
```

데이터마다 어떤 값이 필요한지 정리하면 데이터베이스를 설계하기 쉽다.

## 프로젝트 범위

프로젝트에 포함할 것과 포함하지 않을 것을 정한다.

예:

```text
이번 버전에 포함:
- 할 일 추가
- 할 일 완료
- 할 일 삭제

이번 버전에 포함하지 않음:
- 사용자 간 공유
- 이메일 알림
- 모바일 앱
- 결제 기능
```

범위를 정하면 작업이 지나치게 커지는 것을 막을 수 있다.

## 작업 목록

요구사항을 실제 작업으로 나눈다.

예:

```text
1. 프로젝트 구조 확인
2. 기본 화면 만들기
3. 입력창 만들기
4. 추가 버튼 만들기
5. 목록 표시하기
6. 완료 기능 만들기
7. 삭제 기능 만들기
8. 데이터 저장하기
9. 오류 처리하기
10. 테스트하기
```

각 작업은 가능한 한 작고 확인할 수 있는 단위로 나눈다.

## 요구사항 변경

프로젝트를 진행하다 보면 요구사항이 변경될 수 있다.

변경 전 확인할 내용:

- 무엇이 바뀌는가?
- 어떤 파일을 수정해야 하는가?
- 기존 기능에 영향을 주는가?
- 데이터 구조가 바뀌는가?
- 테스트를 다시 해야 하는가?
- 작업 시간이 늘어나는가?

변경 내용을 기록하고 기존 요구사항과 비교한다.

## 요구사항 확인 질문

요구사항이 불분명하면 코딩을 시작하기 전에 질문한다.

확인할 내용:

- 누가 사용하는가?
- 가장 중요한 기능은 무엇인가?
- 어떤 화면이 필요한가?
- 데이터는 저장해야 하는가?
- 로그인 기능이 필요한가?
- 모바일에서도 사용해야 하는가?
- 외부 서비스와 연결해야 하는가?
- 무료 도구만 사용해야 하는가?
- 언제까지 어떤 수준으로 완성해야 하는가?

## AI 에이전트의 요구사항 처리 순서

AI 코딩 에이전트는 다음 순서로 작업한다.

1. 사용자의 요청을 한 문장으로 정리한다.
2. 불분명한 부분을 확인한다.
3. 프로젝트 목표를 정리한다.
4. 핵심 기능과 부가 기능을 구분한다.
5. 작업 범위를 정한다.
6. 필요한 파일과 기술을 확인한다.
7. 작업을 작은 단계로 나눈다.
8. 사용자의 요청에 맞는 계획을 제시한다.
9. 계획에 따라 작업한다.
10. 각 단계가 완료되었는지 확인한다.
11. 성공 조건에 따라 테스트한다.
12. 결과와 남은 문제를 설명한다.

## 요구사항 문서 예시

```markdown
# 할 일 관리 앱

## 목표

사용자가 해야 할 일을 기록하고 완료 여부를 관리할 수 있는 웹앱을 만든다.

## 사용자

혼자 일정과 할 일을 관리하려는 사람

## 필수 기능

- 할 일 추가
- 할 일 목록 표시
- 할 일 완료 처리
- 할 일 삭제
- 새로고침 후에도 데이터 유지

## 오류 처리

- 빈 내용은 추가하지 않는다.
- 저장에 실패하면 오류 메시지를 표시한다.
- 오류가 발생해도 프로그램이 갑자기 종료되지 않는다.

## 성공 조건

- 사용자가 할 일을 추가할 수 있다.
- 추가한 할 일이 목록에 표시된다.
- 완료 상태를 변경할 수 있다.
- 할 일을 삭제할 수 있다.
- 저장된 데이터가 다시 표시된다.

## 이번 버전에 포함하지 않는 기능

- 사용자 로그인
- 다른 사람과 공유
- 이메일 알림
- 결제
```

## 코딩 에이전트의 요구사항 원칙

- 요구사항이 불분명하면 추측하지 않는다.
- 사용자의 목표와 요청 범위를 먼저 확인한다.
- 핵심 기능과 부가 기능을 구분한다.
- 기능을 작은 작업으로 나눈다.
- 성공 조건을 정한 뒤 테스트한다.
- 요구사항에 없는 기능을 임의로 추가하지 않는다.
- 작업 범위를 크게 바꾸기 전에 사용자에게 알린다.
- 구현하지 않은 기능을 완성되었다고 말하지 않는다.
