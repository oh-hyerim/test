# 개인정보 프로젝트 보안 체크리스트

이 체크리스트는 개인정보가 들어갈 수 있는 프로젝트를 만들 때 사용한다.

모든 항목을 확인하기 전에는 프로젝트가 안전하다고 단정하지 않는다.

## 사용 방법

각 항목을 확인한 뒤 다음 중 하나로 표시한다.

- `[ ]` 아직 확인하지 않음
- `[x]` 확인함
- `[해당 없음]` 현재 프로젝트와 관계없음
- `[확인 필요]` 추가 검토가 필요함

확인하지 못한 항목은 사용자에게 알리고, 안전하다고 말하지 않는다.

## 1. 프로젝트 시작 전

### 목표와 범위

- [ ] 프로젝트의 목적을 한 문장으로 설명할 수 있는가?
- [ ] 누가 사용하는지 정했는가?
- [ ] 이번 버전에 포함할 기능과 제외할 기능을 정했는가?
- [ ] 실제 개인정보를 사용하지 않고 테스트할 수 있는가?
- [ ] 외부 서비스나 클라우드 사용 여부를 확인했는가?

### 개인정보 종류

- [ ] 어떤 개인정보를 수집하는지 목록으로 작성했는가?
- [ ] 각 정보가 정말 필요한지 확인했는가?
- [ ] 꼭 필요하지 않은 정보는 수집하지 않는가?
- [ ] 이름, 이메일, 전화번호, 주소, 사진, 메모 등 정보의 종류를 구분했는가?
- [ ] 민감할 수 있는 정보가 포함되는지 확인했는가?
- [ ] 실제 개인정보 대신 가짜 테스트 데이터를 사용할 계획인가?

### 보관과 삭제

- [ ] 각 정보를 어디에 저장할지 정했는가?
- [ ] 얼마나 오래 보관할지 정했는가?
- [ ] 사용자가 자신의 데이터를 삭제할 수 있는가?
- [ ] 삭제할 때 데이터베이스와 백업에 남는 범위를 확인했는가?
- [ ] 사용하지 않는 데이터가 계속 보관되지 않는가?

### 접근 권한

- [ ] 누가 어떤 데이터를 볼 수 있는지 정했는가?
- [ ] 사용자는 자신의 데이터만 볼 수 있는가?
- [ ] 관리자와 일반 사용자의 권한을 구분했는가?
- [ ] 권한이 없는 사용자가 주소를 직접 입력해 접근할 수 없는가?
- [ ] 서버에서 권한을 확인할 계획인가?

## 2. 설계 단계

### 인증

- [ ] 로그인이 필요한 기능과 필요하지 않은 기능을 구분했는가?
- [ ] 비밀번호를 평문으로 저장하지 않는가?

- [ ] 로그아웃하면 인증 정보가 무효화되는가?

- [ ] `SameSite` 설정을 확인했는가?

- [ ] 세션 비밀키를 코드에 넣지 않는가?

- [ ] 모든 사용자 입력을 서버에서 검증하는가?
- [ ] 입력값의 형식을 확인하는가?
- [ ] 입력값의 길이를 제한하는가?
- [ ] 빈 입력과 잘못된 값을 처리하는가?
- [ ] 사용자 입력을 SQL 명령어에 직접 연결하지 않는가?
- [ ] 사용자 입력을 운영체제 명령어에 직접 연결하지 않는가?

- [ ] 데이터베이스 접속 정보를 코드에 넣지 않는가?

- [ ] 운영 데이터베이스와 테스트 데이터베이스를 구분했는가?
- [ ] 데이터베이스 사용자에게 필요한 권한만 부여했는가?
- [ ] 데이터베이스 백업 방법을 정했는가?
- [ ] 대량 수정이나 삭제 전에 확인 절차가 있는가?

### 외부 서비스

- [ ] 외부 서비스로 보내는 데이터 목록을 작성했는가?
- [ ] 개인정보가 외부로 전송되는지 확인했는가?
- [ ] 외부 서비스의 비용 발생 여부를 확인했는가?
- [ ] 외부 서비스의 보안과 개인정보 처리방침을 확인했는가?
- [ ] 외부 전송을 중단할 방법이 있는가?
- [ ] 외부 서비스의 API 키를 안전하게 관리하는가?

## 9. 보안 사고가 의심될 때

다음과 같은 상황이 발생하면 즉시 작업을 멈추고 확인한다.

- API 키나 비밀번호가 공개됨
- 다른 사용자의 데이터가 보임
- 비정상적인 로그인 시도가 반복됨
- 알 수 없는 파일이 업로드됨
- 예상하지 않은 외부 전송이 발생함
- 데이터가 삭제되거나 변경됨
- 서버 로그에 이상한 요청이 기록됨

대응 순서:

1. 추가 피해를 막는다.
2. 공개된 키와 토큰을 사용 중지한다.
3. 필요한 자격 증명을 새로 발급한다.
4. 영향을 받은 데이터와 사용자를 확인한다.
5. 로그와 변경 기록을 보존한다.
6. 원인을 확인한다.
7. 수정 후 다시 테스트한다.
8. 필요한 안내와 후속 조치를 진행한다.

## 10. AI 코딩 에이전트 확인 규칙

AI 코딩 에이전트는 프로젝트 작업 전에 이 체크리스트에서 관련 항목을 확인한다.

AI 에이전트는 다음 작업을 사용자에게 알리지 않고 실행하지 않는다.

- 개인정보 수집과 저장
- 개인정보 변경과 삭제
- 데이터베이스 데이터 삭제
- 외부 서비스로 데이터 전송
- API 키와 비밀번호 사용
- 로그인과 권한 변경
- 운영 서버 배포
- 공개 저장소 업로드
- 외부 패키지와 프로그램 설치

AI 에이전트는 다음 내용을 작업 결과에 포함한다.

- 확인한 보안 항목
- 확인하지 못한 항목
- 테스트한 보안 시나리오
- 아직 남은 위험
- 사용자가 직접 확인해야 하는 사항

## 최종 판단

다음 조건을 모두 만족하지 않으면 프로젝트를 안전하다고 단정하지 않는다.

- [ ] 개인정보 수집 범위가 정해져 있다.
- [ ] 데이터 접근 권한이 확인되었다.
- [ ] 서버 입력값 검증이 구현되었다.
- [ ] 비밀번호와 비밀 정보가 안전하게 관리된다.
- [ ] 오류와 로그에 민감 정보가 없다.
- [ ] 보안 테스트를 실행했다.
- [ ] 배포 전 환경을 확인했다.
- [ ] 백업과 복구 방법이 있다.
- [ ] 미확인 위험을 기록했다.
