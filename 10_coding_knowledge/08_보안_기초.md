# 보안 기초

## 보안이란?

보안은 프로그램과 데이터를 허가받지 않은 사람이나 프로그램으로부터 보호하는 것이다.

## API 키와 비밀번호

API 키, 비밀번호, 토큰은 다른 사람에게 공개하면 안 되는 중요한 정보이다.

실제 API 키나 비밀번호를 코드에 직접 작성하지 않는다.

```javascript
const apiKey = "실제_API_키";
const password = "실제_비밀번호";
```

현재 사용 중인 로컬 Ollama와 로컬 모델만 사용할 때는 API 키가 필요하지 않다.

## 환경변수

환경변수는 프로그램의 설정값을 코드 파일 밖에 따로 보관하는 방법이다.

민감한 정보는 코드에 직접 작성하지 않고 환경변수로 관리할 수 있다.

예시:

```javascript
const apiKey = process.env.API_KEY;
```

환경변수에 실제 API 키를 넣는 상황은 나중에 외부 AI 서비스나 외부 서비스를 사용할 때 발생할 수 있다.

현재는 실제 API 키를 만들거나 입력할 필요가 없다.

## .env 파일

웹 프로젝트에서는 API 키나 데이터베이스 주소 같은 설정값을 `.env` 파일에 저장하기도 한다.

예시:

```text
API_KEY=여기에_실제_API_키
DATABASE_URL=여기에_데이터베이스_주소
```

`.env` 파일은 비밀번호나 API 키가 들어갈 수 있으므로 GitHub에 공개하지 않는다.

프로젝트의 `.gitignore` 파일에 다음 내용을 추가하면 된다.

```text
.env
```

## 사용자 입력 확인

사용자가 입력한 내용은 항상 확인해야 한다.

확인해야 하는 내용:

- 입력값이 비어 있지 않은가?
- 예상한 형식인가?
- 너무 긴 값은 아닌가?
- 허용하지 않은 문자가 포함되어 있지 않은가?

## SQL 인젝션

SQL 인젝션은 사용자의 입력이 SQL 명령어처럼 실행되는 보안 문제이다.

사용자 입력을 SQL 문자열에 직접 이어 붙이지 않는다.

나쁜 예:

```javascript
const query = "SELECT * FROM users WHERE name = '" + userName + "'";
```

데이터베이스가 제공하는 파라미터 바인딩이나 안전한 ORM을 사용해야 한다.

## XSS

XSS는 악성 JavaScript가 웹페이지에서 실행되는 보안 문제이다.

사용자가 입력한 HTML이나 JavaScript를 화면에 표시할 때는 안전하게 처리해야 한다.

## 인증과 권한

인증은 사용자가 누구인지 확인하는 것이다.

예:

- 로그인
- 비밀번호 확인
- 일회용 인증번호

권한은 인증된 사용자가 무엇을 할 수 있는지 확인하는 것이다.

예:

- 일반 사용자는 자신의 글만 수정할 수 있다.
- 관리자만 사용자를 삭제할 수 있다.

로그인했다고 해서 모든 작업을 허용하면 안 된다.

## 파일 업로드

파일 업로드 기능을 만들 때는 다음을 확인한다.

- 허용할 파일 종류
- 파일 크기 제한
- 파일 이름 처리
- 저장 위치
- 실행 가능한 파일 차단
- 악성 파일 검사

## 보안 작업 원칙

코딩 에이전트는 다음 내용을 코드에 직접 포함하지 않는다.

- 실제 API 키
- 실제 비밀번호
- 개인 인증 토큰
- 개인정보
- 운영 서버 접속 정보

코딩 에이전트는 다음 작업 전에 사용자에게 알린다.

- 외부 서비스에 데이터를 보내는 작업
- API 키를 사용하는 작업
- 데이터베이스에 접속하는 작업
- 파일을 공개 저장소에 올리는 작업
- 로그인이나 권한을 변경하는 작업

## 보안 문제가 의심될 때

API 키나 비밀번호가 공개되었다면 다음 순서로 대응한다.

1. 공개된 키를 즉시 사용 중지한다.
2. 새로운 키를 발급한다.
3. 코드와 Git 기록에서 기존 키를 제거한다.
4. 환경변수로 변경한다.
5. 이미 외부에 공개되었는지 확인한다.

## 보안 기본 원칙

- 모르는 명령어를 함부로 실행하지 않는다.
- 인터넷에서 복사한 코드를 그대로 신뢰하지 않는다.
- 민감한 정보를 채팅이나 GitHub에 올리지 않는다.
- 필요한 권한만 부여한다.
- 데이터를 외부로 보내기 전에 사용자에게 알린다.
- 보안과 관련된 내용은 추측하지 않고 확인한다.
