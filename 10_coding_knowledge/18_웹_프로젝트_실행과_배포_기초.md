# 웹 프로젝트 실행과 배포 기초

## 웹 프로젝트 실행이란?

웹 프로젝트 실행은 작성한 코드를 컴퓨터에서 실제로 작동시키는 것이다.

실행하면 브라우저에서 웹페이지를 확인하거나, 터미널에서 서버가 작동하는 모습을 확인할 수 있다.

## 개발 환경과 운영 환경

### 개발 환경

개발 환경은 프로그램을 만들고 수정하고 테스트하는 환경이다.

개발 중에는 다음과 같은 작업을 한다.

- 코드 작성
- 오류 수정
- 기능 테스트
- 화면 확인
- 개발용 서버 실행

### 운영 환경

운영 환경은 실제 사용자가 이용하는 환경이다.

운영 환경에서는 다음을 중요하게 생각한다.

- 안정적인 실행
- 보안
- 빠른 응답
- 데이터 보호
- 오류 기록
- 백업

개발 환경의 설정을 그대로 운영 환경에 사용하지 않는다.

## 프로젝트 실행 전 확인할 것

프로젝트를 실행하기 전에 다음을 확인한다.

1. 프로젝트 폴더가 맞는지 확인한다.
2. `package.json` 파일이 있는지 확인한다.
3. 필요한 패키지가 설치되어 있는지 확인한다.
4. 실행 명령어를 확인한다.
5. 필요한 환경변수가 설정되어 있는지 확인한다.
6. 사용 중인 포트가 다른 프로그램과 겹치지 않는지 확인한다.

현재 위치를 확인하는 PowerShell 명령어:

```powershell
Get-Location
```

프로젝트 파일을 확인하는 PowerShell 명령어:

```powershell
Get-ChildItem
```

## 패키지 설치

Node.js 프로젝트에 필요한 패키지를 설치하려면 프로젝트 폴더에서 다음 명령어를 실행한다.

```powershell
npm install
```

이 명령어는 `package.json`에 기록된 패키지를 설치한다.

## 프로젝트 실행 명령어 확인

`package.json`의 `scripts` 항목에서 실행 명령어를 확인한다.

예시:

```json
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}
```

개발 서버를 실행하는 명령어:

```powershell
npm run dev
```

프로젝트를 빌드하는 명령어:

```powershell
npm run build
```

빌드 결과를 미리 확인하는 명령어:

```powershell
npm run preview
```

프로젝트마다 실행 명령어가 다를 수 있으므로 `package.json`을 먼저 확인한다.

## 개발 서버

개발 서버는 코드를 수정하면서 결과를 쉽게 확인할 수 있도록 도와주는 서버이다.

개발 서버를 실행하면 보통 다음과 같은 주소가 표시된다.

```text
http://localhost:3000
```

또는:

```text
http://localhost:5173
```

브라우저에서 표시된 주소를 열면 웹페이지를 확인할 수 있다.

## localhost란?

`localhost`는 현재 사용 중인 컴퓨터를 가리키는 주소이다.

예시:

```text
http://localhost:3000
```

위 주소는 인터넷에 공개된 웹사이트가 아니라 사용자님의 컴퓨터에서 실행 중인 개발 서버에 접속하는 주소이다.

## 포트란?

포트는 한 컴퓨터에서 실행 중인 프로그램을 구분하는 번호이다.

예시:

```text
http://localhost:3000
http://localhost:5173
```

위 주소에서 `3000`과 `5173`이 포트 번호이다.

이미 다른 프로그램이 같은 포트를 사용하고 있으면 포트 충돌이 발생할 수 있다.

## 포트 충돌

포트 충돌이 발생하면 다음과 같은 문제가 생길 수 있다.

- 서버가 시작되지 않음
- 주소에 접속되지 않음
- 이미 사용 중인 포트라는 오류가 표시됨

해결 방법:

1. 이미 실행 중인 개발 서버가 있는지 확인한다.
2. 사용하지 않는 서버를 종료한다.
3. 다른 포트 번호를 사용한다.
4. 어떤 프로그램이 포트를 사용하는지 확인한다.

서버를 종료할 때는 실행 중인 터미널에서 다음 키를 누른다.

```text
Ctrl + C
```

## 웹 프로젝트 빌드

빌드는 개발용 코드를 실제 배포에 사용할 파일로 변환하는 과정이다.

빌드 명령어 예시:

```powershell
npm run build
```

빌드가 성공하면 보통 다음과 같은 폴더가 만들어진다.

```text
dist/
```

또는:

```text
build/
```

프로젝트 종류에 따라 빌드 결과 폴더의 이름이 다를 수 있다.

## 빌드 전 확인할 것

빌드하기 전에 다음을 확인한다.

- 문법 오류가 없는가?
- 타입 오류가 없는가?
- 필요한 환경변수가 있는가?
- 이미지와 파일 경로가 올바른가?
- API 주소가 올바른가?
- 테스트가 통과했는가?

빌드가 실패하면 오류 메시지 전체를 확인한다.

## 정적 웹사이트

정적 웹사이트는 서버에서 복잡한 계산을 하지 않고 HTML, CSS, JavaScript 파일을 제공하는 웹사이트이다.

정적 웹사이트에 포함될 수 있는 파일:

- `index.html`
- `style.css`
- `script.js`
- 이미지 파일
- 글꼴 파일

정적 웹사이트는 비교적 간단하게 배포할 수 있다.

## 백엔드가 있는 웹 프로젝트

백엔드가 있는 웹 프로젝트는 서버 프로그램이 실행되어야 한다.

백엔드는 다음과 같은 작업을 처리할 수 있다.

- 로그인
- 데이터베이스 연결
- API 제공
- 파일 업로드
- 사용자 권한 확인
- 결제 처리

백엔드가 있는 프로젝트를 배포할 때는 프론트엔드뿐 아니라 서버와 데이터베이스도 준비해야 한다.

## 배포란?

배포는 만든 프로그램을 다른 사람이 사용할 수 있는 환경에 올리는 것이다.

배포 후에는 사용자가 인터넷을 통해 웹사이트에 접속할 수 있다.

## 배포 전 확인할 것

배포하기 전에 다음을 확인한다.

1. 프로그램이 로컬에서 정상적으로 실행되는가?
2. 빌드가 성공하는가?
3. 테스트가 통과했는가?
4. 민감한 정보가 코드에 포함되어 있지 않은가?
5. `.env` 파일이 공개되지 않는가?
6. 운영 환경용 환경변수가 설정되어 있는가?
7. 데이터베이스를 백업했는가?
8. 오류가 발생했을 때 확인할 로그가 있는가?
9. 실제 사용자에게 영향을 주는 변경인지 확인했는가?
10. 배포 후 되돌릴 방법이 있는가?

## 환경변수와 배포

개발 환경과 운영 환경의 환경변수는 다를 수 있다.

예시:

```text
개발 환경:
API_URL=http://localhost:3000
APP_MODE=development
```

```text
운영 환경:
API_URL=https://api.example.com
APP_MODE=production
```

운영 환경의 API 키, 비밀번호, 데이터베이스 주소는 공개하지 않는다.

## 도메인

도메인은 웹사이트에 접속하기 위한 이름이다.

예시:

```text
example.com
```

사용자는 숫자로 된 서버 주소 대신 도메인을 사용해 웹사이트에 접속한다.

## HTTPS

HTTPS는 브라우저와 서버 사이의 통신을 암호화하는 방식이다.

로그인 정보와 개인정보를 보호하려면 운영 웹사이트에서 HTTPS를 사용하는 것이 중요하다.

## 배포 후 확인

배포가 끝난 뒤에는 다음을 확인한다.

- 웹사이트가 열리는가?
- 주요 화면이 정상적으로 표시되는가?
- 로그인 기능이 작동하는가?
- API 요청이 성공하는가?
- 데이터가 정상적으로 저장되는가?
- 이미지와 파일이 표시되는가?
- 브라우저 콘솔에 오류가 없는가?
- 서버 로그에 오류가 없는가?

## 배포 실패 시 대응

배포에 실패하면 다음 순서로 확인한다.

1. 배포 오류 메시지 전체를 확인한다.
2. 빌드가 로컬에서 성공하는지 확인한다.
3. 환경변수가 올바르게 설정되었는지 확인한다.
4. 필요한 패키지가 설치되었는지 확인한다.
5. 파일 경로와 대소문자를 확인한다.
6. 서버 로그를 확인한다.
7. 최근 변경사항을 확인한다.
8. 필요한 경우 이전에 정상 작동하던 버전으로 되돌린다.

## 되돌리기

배포 후 문제가 발생하면 이전에 정상적으로 작동하던 버전으로 되돌릴 수 있어야 한다.

되돌리기 전에 다음을 확인한다.

- 어떤 변경이 문제를 만들었는가?
- 이전 버전이 저장되어 있는가?
- 데이터베이스 변경이 있었다면 복구할 수 있는가?
- 사용자에게 어떤 영향을 주는가?

## 코딩 에이전트의 실행 원칙

코딩 에이전트는 프로젝트를 실행하거나 배포하기 전에 다음을 확인한다.

- 현재 프로젝트 폴더가 맞는가?
- 실행할 명령어가 무엇인가?
- 명령어가 어떤 변경을 만드는가?
- 포트나 서버를 사용하는가?
- 외부 서비스에 연결하는가?
- 데이터가 변경되는가?
- 운영 환경에 영향을 주는가?

## 코딩 에이전트의 배포 원칙

코딩 에이전트는 다음 작업을 실행하기 전에 사용자에게 알린다.

- 운영 서버 배포
- 외부에 웹사이트 공개
- 도메인 연결
- 데이터베이스 변경
- 운영 데이터 수정 또는 삭제
- 결제나 외부 서비스 연결
- 공개 저장소에 코드 업로드

배포하지 않은 상태를 배포했다고 말하지 않는다.

테스트하지 않은 기능을 정상적으로 작동한다고 말하지 않는다.

## 웹 프로젝트 실행과 배포의 기본 순서

1. 프로젝트 폴더를 연다.
2. 프로젝트 파일을 확인한다.
3. `package.json`을 확인한다.
4. 필요한 패키지를 설치한다.
5. 개발 서버를 실행한다.
6. 브라우저에서 기능을 확인한다.
7. 오류를 수정한다.
8. 테스트를 실행한다.
9. 빌드한다.
10. 빌드 결과를 확인한다.
11. 배포 전에 민감한 정보를 확인한다.
12. 사용자의 확인 후 배포한다.
13. 배포 후 웹사이트와 주요 기능을 확인한다.
