# 디버깅과 오류 해결

## 디버깅이란?

디버깅은 프로그램에 생긴 문제의 원인을 찾아 해결하는 과정이다.

오류가 발생했다고 해서 코드를 무작정 여러 군데 고치면 안 된다. 먼저 오류 메시지를 읽고 문제가 생긴 위치와 원인을 확인해야 한다.

## 오류 메시지란?

오류 메시지는 프로그램이 무엇을 할 수 없었는지 알려주는 설명이다.

오류 메시지에서 다음 정보를 확인한다.

- 오류의 종류
- 오류가 발생한 파일
- 오류가 발생한 줄 번호
- 오류에 대한 설명

## 오류가 발생했을 때의 순서

1. 오류 메시지를 처음부터 끝까지 읽는다.
2. 오류가 발생한 파일과 줄 번호를 확인한다.
3. 해당 줄 주변의 코드를 확인한다.
4. 오류가 발생하기 직전에 무엇을 변경했는지 확인한다.
5. 원인을 하나씩 확인한다.
6. 한 가지 방법만 수정한 뒤 다시 실행한다.
7. 해결되었는지 확인한다.

## 오류의 종류

### 문법 오류

코드의 문법이 올바르지 않을 때 발생한다.

예를 들어 괄호나 따옴표를 닫지 않으면 문법 오류가 발생할 수 있다.

```javascript
const message = "안녕하세요;
```

위 코드는 문자열을 시작한 따옴표를 닫지 않았기 때문에 오류가 발생한다.

올바른 코드는 다음과 같다.

```javascript
const message = "안녕하세요";
```

### 실행 오류

문법은 맞지만 프로그램을 실행하는 중 문제가 발생하는 경우이다.

예를 들어 존재하지 않는 파일을 읽으려고 하면 실행 오류가 발생할 수 있다.

### 논리 오류

프로그램은 실행되지만 원하는 결과가 나오지 않는 경우이다.

예를 들어 더하기를 해야 하는데 실수로 빼기를 사용하면 논리 오류가 발생한다.

## 오류를 설명할 때 필요한 정보

다른 사람이나 AI에게 오류 해결을 요청할 때는 다음 정보를 함께 제공한다.

- 오류 메시지 전체
- 오류가 발생한 명령어
- 오류가 발생한 파일 이름
- 오류가 발생하기 전 변경한 내용
- 사용 중인 운영체제
- 사용 중인 프로그램과 버전
- 내가 기대한 결과
- 실제로 나타난 결과

## 잘못된 해결 방법

다음과 같은 방법은 피한다.

- 오류 메시지를 읽지 않고 코드를 무작정 수정하기
- 여러 파일을 한꺼번에 수정하기
- 원인을 모른 채 프로그램을 다시 설치하기
- 오류 메시지의 일부만 보여주기
- 해결되지 않았는데 해결되었다고 판단하기
- 인터넷에서 찾은 명령어를 의미도 모른 채 실행하기

## AI에게 오류를 보여줄 때

오류를 해결해달라고 요청할 때는 오류 메시지를 가능한 한 그대로 전달한다.

예시:

```text
Windows PowerShell에서 다음 명령어를 실행했습니다.

ollama run llama3.2:1b

다음 오류가 발생했습니다.

오류 메시지 전체를 여기에 붙여넣습니다.

저는 다음 결과를 기대했습니다.

모델이 실행되고 답변하는 것

실제로는 다음 결과가 나왔습니다.

오류가 표시되고 실행되지 않았습니다.
```

## 수정 후 확인

문제를 수정한 뒤에는 다음을 확인한다.

1. 같은 명령어를 다시 실행한다.
2. 같은 오류가 다시 발생하는지 확인한다.
3. 원래 기대했던 결과가 나오는지 확인한다.
4. 다른 기능이 망가지지 않았는지 확인한다.
5. 무엇을 수정했는지 기록한다.

## 에이전트의 오류 대응 원칙

코딩 에이전트는 오류가 발생하면 다음 원칙을 지킨다.

- 오류 메시지를 사용자에게 숨기지 않는다.
- 확인하지 않은 내용을 사실처럼 말하지 않는다.
- 원인을 하나씩 확인한다.
- 위험한 명령어를 실행하기 전에 설명한다.
- 수정 후 반드시 다시 테스트한다.
- 해결되지 않았으면 해결되지 않았다고 말한다.
